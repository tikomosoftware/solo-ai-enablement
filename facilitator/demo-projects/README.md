# デモ用サンプルプロジェクト集

このディレクトリは、全4回の説明会で使う小さなサンプルプロジェクトをまとめたものです。

参加者は登壇者の画面を見ながら流れを理解し、あとで同じ題材を使って自分の手元でも練習できます。

## 使い方

この教材では、参加者向けの基本導線を **Visual Studio Code + Claude Code extension** とします。

CLIの使い方は本編の主題にしません。CLIに慣れている人は同じ依頼文をターミナル版のClaude Codeで使っても構いませんが、説明会ではVS Code上で次の流れを見せます。

1. VS Codeでサンプルフォルダを開く
2. Claude Codeのパネルを開く
3. 依頼文を貼り付ける
4. 変更前の方針を読む
5. 実装を依頼する
6. VS Codeの差分表示で変更を見る
7. Markdownプレビューやブラウザで結果を確認する

各フォルダには次のものを入れています。

- `README.md`: サンプルプロジェクトの概要
- `DEMO-STEPS.md`: 登壇者が実演するときの手順
- サンプルのソースやドキュメント

はじめて参加する人には、先に [事前準備: VS CodeでClaude Codeを使う](../../ai-development-harness/template/docs/vscode-claude-code-guide.md) を共有してください。

## 4回分の題材

| 回 | フォルダ | ねらい |
| --- | --- | --- |
| 第1回 | `01-docs-copy-fix/` | 変更前に構成を調べ、READMEの小さな文言修正を依頼する |
| 第2回 | `02-static-page-fix/` | HTML/CSS/JSの小さな表示修正を計画、実装、差分確認まで行う |
| 第3回 | `03-form-validation-workflow/` | チーム運用を想定し、修正方針、レビュー観点、確認手順をそろえる |
| 第4回 | `04-project-onboarding/` | 実プロジェクト導入を想定し、プロジェクト固有ルールと最初の改善を作る |

## 実演時の共通ルール

- いきなり実装させず、最初に調査と方針だけを依頼する
- 触るファイル、影響範囲、確認方法を先に聞く
- 修正後は差分を確認する
- 不安があれば止める
- 削除、履歴操作、force push、本番環境操作は扱わない
- ターミナル操作そのものを学習目的にしない

## 参加者へ伝えること

このサンプルは「AIに任せればよい」と見せるためのものではありません。

目的は、人間が安全に小さく依頼し、結果を確認しながら進める感覚をつかむことです。
