# 第4回 デモ手順: 実プロジェクトへ広げる前の確認

## 目的

実プロジェクトに入る前に、固有ルール、禁止事項、最初に試す小さな改善、確認方法をAIに整理させる流れを練習します。

## 登壇者の流れ

1. VS Codeで `04-project-onboarding` フォルダを開く
2. `PROJECT-RULES.md` を見せる
3. VS CodeのClaude Codeパネルで、AIにルールを読んだうえで今回の修正方針を整理させる
4. `index.html` をブラウザで開き、検索対象が質問文だけになっていることを確認する
5. 回答文も検索対象にする最小修正を依頼する
6. VS Codeの差分表示で、ルールに反する変更がないか確認する
7. `パスワード`、`管理者` などで検索して確認する
8. 最後に、実プロジェクト導入時のチェック項目をAIにまとめさせる

## 最初に使う依頼文

```text
このサンプルは実プロジェクト導入の練習です。
PROJECT-RULES.md を読んだうえで、FAQ検索を小さく改善したいです。
まだ変更せず、今回できる最小修正、触るファイル、確認方法、ルール上注意すべき点を整理してください。
```

## 実装を依頼する文

```text
方針は問題ありません。
FAQ検索で、質問文だけでなく回答文も検索対象になるように最小限の変更をしてください。
修正後に差分、確認手順、実プロジェクトで同じことをする場合の注意点を説明してください。
```

## 確認ポイント

- 質問文に含まれる語で検索できるか
- 回答文にだけ含まれる語でも検索できるか
- `PROJECT-RULES.md` に反する変更がないか
- FAQデータの内容が勝手に大きく変わっていないか
- 実プロジェクトでの注意点が説明されているか
- VS Code上でルール、差分、動作確認の3つをつなげて見られたか

## 参加者の練習課題

実装はせず、自分の担当プロジェクトで最初にAIへ依頼できそうな小さな改善を1つ選び、以下をAIに整理させてください。

- 触る予定のファイル
- 影響範囲
- 確認方法
- レビュー依頼先
- やらない方がよいこと
