# Claude Code強機能の扱い方

## 目的

Claude Codeには、通常のチャットやコード修正以外にも多くの強力な機能があります。

このドキュメントは、それらをすべて説明するための資料ではありません。チームで安全に使い始めるために、最初から説明するもの、使う前に相談するもの、当面は使わないものを分類します。

## 基本方針

- 最初から全機能を使おうとしない。
- まずは調査、方針作成、小さな修正、差分確認、テスト確認に絞る。
- 自動実行、外部連携、永続設定、権限変更は慎重に扱う。
- チームで使う機能は、個人の便利設定ではなくチームルールとして確認する。
- 使い方が分からない機能は、無理に試さず、目的とリスクを整理してから相談する。

| 要相談 | MCP連携 | 接続先、権限、情報管理を確認してから使う | 外部サービスや社内情報へアクセスできる場合があるため |
| 要相談 | サブエージェント | 役割と権限を決めてから使う | 並行作業や専門分担に便利だが、責任範囲が見えにくくなるため |
| 要相談 | Skills、プラグイン、拡張機能 | 導入目的と管理者を決めてから使う | 機能追加により挙動、権限、保守対象が増えるため |
| 要相談 | ブラウザ操作、GUI操作 | 対象環境と確認手順を決めてから使う | 認証済みページや社内画面を操作する可能性があるため |
| 要相談 | GitHub、Slack、カレンダーなどの外部連携 | 接続範囲を確認してから使う | 通知、投稿、PR操作など、チームに影響する操作が起きるため |
| 要相談 | 並列セッション、複数エージェント作業 | 変更範囲を分けてから使う | 競合や見落としが増えやすいため |
| 要相談 | 長時間の自動作業 | 途中確認の方法を決めてから使う | 人間のレビュー前に変更が広がりすぎる可能性があるため |
| 要相談 | 画像、PDF、スライドなどの生成 | 用途とレビュー方法を決めてから使う | 生成物の正確性、権利、ブランド表現の確認が必要なため |
| 原則使わない | 削除、reset、clean、rebase、force pushの自動実行 | 使わない | 作業や履歴を失う可能性があるため |
| 原則使わない | 本番環境への操作 | 使わない | 障害やデータ破壊につながる可能性があるため |
| 原則使わない | 本番DB、顧客データ、秘密情報への直接操作 | 使わない | 情報漏えい、データ破壊、監査リスクがあるため |
| 原則使わない | 承認なしの依存更新、lockfile大規模変更 | 使わない | 影響範囲が広く、ビルドや実行環境を壊す可能性があるため |
| 原則使わない | AIによる自動コミット、自動push | 使わない | 人間の差分確認、テスト、レビューを飛ばしやすいため |
| 原則使わない | 認証情報、秘密鍵、`.env` の読み書き | 使わない | 機密情報をAIに渡すリスクがあるため |
| 原則使わない | チーム未承認の外部サービス連携 | 使わない | 接続先、保存先、権限範囲が不明なまま情報が流れる可能性があるため |

## 説明会で扱う範囲

初心者向け、初回説明会、30分説明会では、次だけ扱います。

- プロジェクトルートで起動する
- 変更なしで調査する
- 実装前に方針を出してもらう
- 小さな修正を依頼する
- 差分を見る
- テストや確認観点を聞く
- 危険操作は止める

次の機能は、初回説明会では深く扱いません。

- Hooks
- MCP
- サブエージェント
- Skills、プラグイン
- 外部サービス連携
- 並列セッション
- 長時間の自動作業
- 自動コミット、自動push

存在だけ紹介する場合も、「便利だから各自で試してください」とは言いません。使う場合はチームで目的、権限、レビュー方法を決めます。

## 使う前に確認すること

要相談の機能を使いたい場合は、次を整理してから相談します。

- 何のために使うのか。
- 対象ファイル、対象サービス、対象データは何か。
- AIが実行できる操作はどこまでか。
- 失敗した場合に何が壊れるか。
- 人間がどこで差分や結果を確認するか。
- チームの誰が設定を管理するか。
- 無効化、停止、削除の方法は分かっているか。

## AIへの指示例

```text
Claude Codeの高度な機能は、こちらが明示的に依頼するまで使わないでください。
Hooks、MCP、サブエージェント、外部サービス連携、自動コミット、自動pushが必要だと判断した場合は、実行せず、目的、メリット、リスク、必要な承認だけ説明してください。
```

## 見直し

この分類は固定ではありません。

チームで安全に使えることが確認できた機能は、「要相談」から「使ってよい」へ移せます。逆に、事故や混乱が起きた機能は「原則使わない」へ戻します。
