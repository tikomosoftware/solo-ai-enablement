# 実用編

このフォルダは、AI開発支援ツールを実際のチーム開発で使うための実務ガイドです。

導入・セットアップ資料で考え方、安全ルール、起動方法を確認したあとに、「明日からどう使うか」を扱います。

## 対象者

- Claude CodeやGitHub Copilotを開発作業で使い始める人
- チームでAIへの依頼方法をそろえたい人
- 調査、実装、レビュー、テスト確認をAIに手伝わせたい人
- 実プロジェクトで小さく試しながら運用を育てたい人

## この実用編のゴール

- 最初の1週間にやることを決める
- AIへの依頼文の型を持つ
- 小さな修正を安全に依頼する
- レビュー、テスト、PR前確認にAIを使う
- 困ったときに作業を止め、相談できる

## 章一覧

### 1. 最初の1週間の進め方

[01 最初の1週間の進め方](./01_first-week-operation.md)

セットアップ後、いきなり大きな実装を任せず、調査、小さな確認、軽微な修正へ段階的に進むための流れを扱います。

### 2. 依頼文の基本パターン

[02 依頼文の基本パターン](./02_prompt-patterns.md)

調査、方針作成、小さな修正、レビュー、テスト確認など、実務で繰り返し使う依頼の型をまとめます。

### 3. 小さな修正ワークフロー

[03 小さな修正ワークフロー](./03_small-change-workflow.md)

文言修正、README追記、軽微なバグ修正、テスト追加など、影響範囲の小さい変更を安全に進める手順を扱います。

### 4. レビューとテスト確認

[04 レビューとテスト確認](./04_review-and-test.md)

AIに差分説明、レビュー観点、テスト観点、確認漏れの洗い出しを手伝わせる流れを扱います。

### 5. 困ったときの止め方

[05 困ったときの止め方](./05_trouble-stop-guide.md)

AIの提案が大きすぎる、危険操作を含む、差分が読めない、失敗した、という場面で作業を止めて相談するためのガイドです。

## 説明会での扱い方

導入説明では、まず既存の導入・ルール資料を使います。

その後で、実用編を次のように紹介します。

1. ここからは実際の使い方を扱う。
2. 最初は調査と小さな修正だけに絞る。
3. 差分、テスト、レビューは人間が確認する。
4. 困ったら止めて相談する。

## このフォルダで扱わないこと

- Hooks、MCP、サブエージェントなどの高機能活用
- 本番環境や本番DBへの操作
- 大規模リファクタリング
- AIによる自動コミット、自動push
- チーム未承認の外部サービス連携
