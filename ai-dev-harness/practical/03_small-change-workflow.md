# 03. 小さな修正ワークフロー

## この章の目的

AIに小さな修正を依頼するときの流れを決めます。

最初は、影響範囲が狭く、戻しやすく、人間が差分を読める作業から始めます。

## 向いている作業

- READMEやドキュメントの追記
- 表示文言の修正
- 小さなバグの原因調査
- テストケースの追加
- エラーメッセージやログ文言の改善
- 既存コードに沿った軽微な修正

## 向いていない作業

- 大規模リファクタリング
- 複数機能をまたぐ変更
- 設計判断が必要な新機能
- 本番環境や本番DBへの操作
- 依存関係の大きな更新
- 履歴を書き換えるGit操作

## 進め方

### 1. 変更前に調査する

```text
この修正に関係しそうなファイルと影響範囲を調査してください。
まだ変更はしないでください。
```

### 2. 方針を確認する

```text
修正方針を提案してください。
変更予定ファイル、変更内容、確認方法、リスクを整理してください。
```

### 3. 小さく修正する

```text
方針に沿って修正してください。
依頼範囲外の整形、リファクタリング、ファイル移動はしないでください。
```

### 4. 差分を読む

人間が確認すること:

- 依頼した範囲だけ変わっているか。
- 余計な整形やリファクタリングが入っていないか。
- 既存の設計や命名に合っているか。
- テストや確認方法が妥当か。

### 5. 確認する

```text
この変更で実行すべきテストと手動確認を整理してください。
実行できない確認があれば、残るリスクも説明してください。
```

## PR前に確認すること

- 差分を自分で読んだ。
- テストまたは手動確認を行った。
- AIが作った説明をそのまま貼らず、自分の言葉で確認した。
- 不安な点をPRに残した。
- 危険操作や承認が必要な操作をしていない。
