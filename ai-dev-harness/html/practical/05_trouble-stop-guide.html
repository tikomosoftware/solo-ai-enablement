05. 困ったときの止め方

この章の目的

AIの作業中に不安を感じたとき、どこで止めるかを決めます。

止めることは失敗ではありません。むしろ、チームで安全に使うための重要な操作です。

止めるべき場面

  • 変更範囲が想定より大きくなった。
  • 関係ないファイルが変更されている。
  • 削除、移動、大量置換が提案された。
  • git reset、git clean、git rebase、force push が出てきた。
  • 本番環境、DB、秘密情報に触れそうになった。
  • 差分を読んでも意図が分からない。
  • AIの説明と実際の変更が合っていない。
  • テストが失敗した理由が分からない。

まず依頼すること

ここで作業を止めてください。
これ以上ファイルを変更しないでください。
現在の変更済みファイル、実施した内容、未確認の点、次に人間が判断すべきことを整理してください。

人間が確認すること

  • どのファイルが変わったか。
  • 依頼範囲外の変更があるか。
  • 削除や移動が含まれていないか。
  • テストやビルドを実行したか。
  • 元に戻す必要があるか、それとも修正を続けられるか。

相談するときに共有する情報

  • 依頼した内容
  • AIが提案した方針
  • 変更済みファイル
  • 不安に感じた点
  • 実行したコマンド
  • テストや確認の結果

やってはいけないこと

  • 分からないまま追加で大きな修正を依頼する。
  • 差分を読まずにコミットする。
  • 失敗したので reset や clean で戻そうとする。
  • 本番環境やDBで試す。
  • 秘密情報や認証情報をAIに渡す。

再開するとき

再開する場合は、作業範囲を小さくします。

先ほどの作業は範囲が大きかったので、次は変更せずに調査だけしてください。
問題の原因候補と、最小の修正案を整理してください。
