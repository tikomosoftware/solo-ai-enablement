# AI活用・AI開発支援 導入ガイド

AIをこれから使い始める人、チームにAI開発支援を広げる人、実プロジェクトへ安全に導入する人に向けた導入ガイドです。

資料バージョン: 0.5

資料基準日: 2026-06-10

この資料はAI関連の内容を扱うため、製品名、機能名、提供プラン、画面、料金、制限、セキュリティ条件は短期間で変わる可能性があります。特にClaude Code、GitHub Copilot、Claude Security、Fable 5 / Mythos 5などの具体的な製品・モデル情報は、利用前に公式情報と社内ルールで確認してください。

このリポジトリでは、用途の違う資料をフォルダ単位で分けています。各フォルダは別資料として扱い、フォルダをまたぐリンクには依存しない方針です。

## 資料マップと完成度

現時点では、資料セットごとに完成度が異なります。説明会や配布で使う場合は、次のラベルを目安にしてください。

- `ai-general-101/`: 利用可。AI一般の初心者向け基礎資料。AIの基本的な考え方、注意点、ルールを説明する入口資料として利用できます。
- `ai-starter-kit/`: 利用可。AIをほとんど触ったことがない人が、最初に手を動かして試すためのワーク、チートシート、入力判断クイズ、実践例です。
- `ai-dev-101-facilitator/`: 説明会用。説明会を進行する人向けの資料。第0回から第4回までのスライド、台本、メンバー向けメモを含みます。
- `ai-dev-harness/`: 一部利用可。開発者向けの導入・ルール資料。基礎・ルール編は導入説明に使えます。後半の実用編、リファレンス、ツール別ガイドは構成案と短い要点が中心です。
- `ai-dev-advanced/`: 一部利用可。Claude Code高機能活用の検討メニュー。Claude Security、Fable 5 / Mythos 5、安全ガードなどの最近情報を含みます。Markdown原本と共有用HTMLを生成します。現時点では完成版の操作手順ではなく、深掘り候補の一覧です。
- `ai-project-template/`: テンプレート。実プロジェクトへコピーして使う資料。各プロジェクトの事情に合わせて編集する前提です。Markdown原本と共有用HTMLを生成します。

別管理の関連資料として、エンジニア向けにAI活用を実務の仕事単位で整理したワークショップ資料があります。既存コード理解、開発、テスト、レビュー、運用保守、実務利用ルールなどを深く扱います。

まずは資料全体の流れを確認するための地図として見てください。本文は説明会や実プロジェクトで必要になった章から順に追加していきます。

## 日付の読み方

このリポジトリでは、AI関連情報がすぐ古くなる前提で、日付を次のように扱います。

- `資料基準日`: その資料セットの前提や構成を確認した日。
- `最終確認日`: 製品仕様、提供範囲、セキュリティ条件など、変化しやすい情報を確認した日。
- `作成日`: 新規に作成した資料で、初版の日付を残したい場合に使います。

各ファイルの内容が古く見える場合は、本文だけで判断せず、まず資料基準日と最終確認日を確認してください。

一般的な考え方を扱う資料は比較的長く使えますが、具体的な製品操作、権限設定、外部連携、モデル名、プラン名を扱う資料は、説明会や配布の前に見直します。

## フォルダ構成

- `ai-general-101/`: AIをこれから使い始める人向けの基礎記事
- `ai-starter-kit/`: AI初心者が最初に手を動かすための演習・配布資料
- `ai-dev-101-facilitator/`: AI活用やAI開発支援をチームへ展開する担当者向け資料
- `ai-dev-harness/`: チームでAI開発支援ツールを使うための考え方、ルール、ガイド
- `ai-dev-advanced/`: Claude Codeの高機能活用や自動化を検討するための候補一覧
- `ai-project-template/`: 実プロジェクトへコピーして使うためのテンプレート

## 関連資料との使い分け

エンジニア向けワークショップ資料は、このリポジトリとは別管理の関連資料です。資料群としては同じ「AI活用・AI開発支援」の括りですが、役割を分けて扱います。

| 読み手・目的 | 主に見る資料 |
|---|---|
| AI一般の基本的な考え方を説明する | `ai-general-101/` |
| AIをほとんど触ったことがない人に、最初のワークを行う | `ai-starter-kit/` |
| 説明会を設計・進行する | `ai-dev-101-facilitator/` |
| Claude CodeやGitHub Copilotをチーム開発に導入する | `ai-dev-harness/` |
| 実プロジェクトへAI利用ルールやテンプレートを持ち込む | `ai-project-template/` |
| エンジニア向けに、既存コード理解、開発、テスト、レビュー、運用保守でのAI活用を深く説明する | 別管理のエンジニア向けワークショップ資料 |

このリポジトリ内の各フォルダは独立した資料セットとして読めるようにし、関連資料への参照は全体像を案内するためのものとして扱います。

## 読者別の入口

### AI初心者

対象:

- AIを仕事で使い始める人
- 非エンジニアを含むチームメンバー
- まずAIの基本的な使い方と注意点を知りたい人

読む資料:

- `ai-general-101/`
- `ai-starter-kit/`

ゴール:

- AIに頼めること、頼んではいけないことを理解する
- 情報管理と事実確認の基本を押さえる
- AIの回答をそのまま正解として扱わない感覚を持つ

扱わないこと:

- Claude CodeやGitHub Copilotの詳しい開発者向け設定
- Hooks、MCP、サブエージェントなどの高度な自動化
- 実プロジェクトへのテンプレート導入

### 開発者

対象:

- Claude CodeやGitHub Copilotを開発作業に使う人
- AI支援ツールを使って調査、実装、レビュー、テストを行う人

読む資料:

- `ai-dev-harness/`

ゴール:

- プロジェクトルートで安全に起動する
- ルールを読み、差分、テスト、レビュー込みで使う
- 危険操作や情報管理の境界を理解する

扱わないこと:

- AIそのものの一般的な入門説明
- 説明会の進め方
- 実プロジェクトへコピーするテンプレート本体

### 導入・運用担当者

対象:

- チームリーダー
- レビュアー
- AI活用やAI開発支援の展開担当者

読む資料:

- `ai-dev-101-facilitator/`
- `ai-project-template/`

ゴール:

- 説明会を設計する
- 実プロジェクトへテンプレートを導入する
- チームルールを育て、見直し続ける

扱わないこと:

- 参加者向けの入門説明をすべてここに集約すること
- 最新機能の細かい使い方を網羅し続けること

### Claude Codeの高機能活用を検討する人

**注意:** この入口と `ai-dev-advanced/` は、現時点では高機能活用の構成案と検討メニューです。各機能の詳しい設定手順や実例は、まだ十分には作り込んでいません。

この入口は、Claude Codeの基本的な使い方を覚えたあとに、さらに便利な使い方やチーム向けの自動化を検討するための場所です。

現時点では、すべての高機能を詳しく説明する完成版ではなく、「どんな機能があり、どの順番で検討するとよいか」を整理するための案内として扱います。説明会や実プロジェクトで要望が出たものから、個別の章を深掘りしていきます。

対象:

- Claude Codeの基本操作に慣れた開発者
- Hooks、MCP、サブエージェントなどを検討する人
- チームの反復作業や自動化を整備したい人
- AI開発支援を個人利用からチーム運用へ広げたい人

読む資料:

- `ai-dev-advanced/`

ゴール:

- Claude Codeの高機能にどんな選択肢があるかを把握する
- すぐ試す機能と、まだ導入しない機能を分けて考える
- 説明会後の要望に応じて、深掘りする章を選ぶ
- 導入前に目的、権限、情報管理、レビュー方法を確認する
- 自動化によって楽になる作業と、確認を残すべき作業を切り分ける

扱わないこと:

- 初回説明会で全機能を詳しく説明すること
- チーム未承認の外部連携や自動実行をすすめること
- 高機能を使うこと自体を目的にすること

## 資料の扱い

- 各フォルダは、それぞれ独立した資料セットとして管理します。
- フォルダ間の関係は、このREADMEで案内します。
- 各資料セットの本文には、別フォルダの資料を前提にしたMarkdownリンクを置きません。
- 別資料を案内する場合は、具体的なリンクではなく「別資料を参照」「開発者向け資料を参照」のように書きます。
- 同じ資料セット内でも、フォルダをまたぐリンクは必要最小限にします。画像など、表示に必要なアセットリンクは例外です。
- 必要な説明は、それぞれのフォルダ内のREADMEに書きます。
- HTMLがあるフォルダでは、Markdownを原本、HTMLを閲覧・共有用の生成物として扱います。

## ローカルでHTMLを生成する

```bash
npm run build
```

現在のHTML生成対象は `ai-general-101/`、`ai-starter-kit/`、`ai-dev-advanced/`、`ai-dev-harness/`、`ai-project-template/` です。生成物は各フォルダ内の `html/` に作成します。

## GitHub Actions

GitHub ActionsでHTMLを自動生成する場合も、対象フォルダ単位で設定します。フォルダ構成を変えた場合は、ワークフロー内の監視パスと出力先もあわせて見直します。
