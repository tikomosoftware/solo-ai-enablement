# AI活用・AI開発支援 導入ガイド

AIをこれから使い始める人、チームにAI開発支援を広げる人、実プロジェクトへ安全に導入する人に向けた導入ガイドです。

このリポジトリでは、用途の違う資料をフォルダ単位で分けています。各フォルダは別資料として扱い、フォルダをまたぐリンクには依存しない方針です。

## フォルダ構成

- `ai-dev-101/`: AIをこれから使い始める人向けの基礎記事
- `ai-dev-101-facilitator/`: AI活用やAI開発支援をチームへ展開する担当者向け資料
- `ai-dev-harness/`: チームでAI開発支援ツールを使うための考え方、ルール、ガイド
- `ai-dev-advanced/`: Claude Codeの高機能活用や自動化を検討するための候補一覧
- `ai-project-template/`: 実プロジェクトへコピーして使うためのテンプレート

## 読者別の入口

### AI初心者

対象:

- AIを仕事で使い始める人
- 非エンジニアを含むチームメンバー
- まずAIの基本的な使い方と注意点を知りたい人

読む資料:

- `ai-dev-101/`

ゴール:

- AIに頼めること、頼んではいけないことを理解する
- 情報管理と事実確認の基本を押さえる
- AIの回答をそのまま正解として扱わない感覚を持つ

扱わないこと:

- Claude CodeやGitHub Copilotの詳しい開発者向け設定
- Hooks、MCP、サブエージェントなどの高度な自動化
- 実プロジェクトへのテンプレート導入

### 開発者

対象:

- Claude CodeやGitHub Copilotを開発作業に使う人
- AI支援ツールを使って調査、実装、レビュー、テストを行う人

読む資料:

- `ai-dev-harness/`

ゴール:

- プロジェクトルートで安全に起動する
- ルールを読み、差分、テスト、レビュー込みで使う
- 危険操作や情報管理の境界を理解する

扱わないこと:

- AIそのものの一般的な入門説明
- 説明会の進め方
- 実プロジェクトへコピーするテンプレート本体

### 導入・運用担当者

対象:

- チームリーダー
- レビュアー
- AI活用やAI開発支援の展開担当者

読む資料:

- `ai-dev-101-facilitator/`
- `ai-project-template/`

ゴール:

- 説明会を設計する
- 実プロジェクトへテンプレートを導入する
- チームルールを育て、見直し続ける

扱わないこと:

- 参加者向けの入門説明をすべてここに集約すること
- 最新機能の細かい使い方を網羅し続けること

### 高機能活用を検討する人

この入口は、Claude Codeの基本的な使い方を覚えたあとに、さらに便利な使い方やチーム向けの自動化を検討するための場所です。

現時点では、すべての高機能を詳しく説明する完成版ではなく、「どんな機能があり、どの順番で検討するとよいか」を整理するための案内として扱います。説明会や実プロジェクトで要望が出たものから、個別の章を深掘りしていきます。

対象:

- Claude Codeの基本操作に慣れた開発者
- Hooks、MCP、サブエージェントなどを検討する人
- チームの反復作業や自動化を整備したい人
- AI開発支援を個人利用からチーム運用へ広げたい人

読む資料:

- `ai-dev-advanced/`

ゴール:

- Claude Codeの高機能にどんな選択肢があるかを把握する
- すぐ試す機能と、まだ導入しない機能を分けて考える
- 説明会後の要望に応じて、深掘りする章を選ぶ
- 導入前に目的、権限、情報管理、レビュー方法を確認する
- 自動化によって楽になる作業と、確認を残すべき作業を切り分ける

扱わないこと:

- 初回説明会で全機能を詳しく説明すること
- チーム未承認の外部連携や自動実行をすすめること
- 高機能を使うこと自体を目的にすること

## 資料の扱い

- 各フォルダは、それぞれ独立した資料セットとして管理します。
- 別フォルダの資料を前提にしたMarkdownリンクは置きません。
- 必要な説明は、それぞれのフォルダ内のREADMEに書きます。
- HTMLがあるフォルダでは、Markdownを原本、HTMLを閲覧・共有用の生成物として扱います。

## ローカルでHTMLを生成する

```bash
npm run build
```

現在のHTML生成対象は `ai-dev-101/` と `ai-dev-harness/` です。生成物は各フォルダ内の `html/` に作成します。

## GitHub Actions

GitHub ActionsでHTMLを自動生成する場合も、対象フォルダ単位で設定します。フォルダ構成を変えた場合は、ワークフロー内の監視パスと出力先もあわせて見直します。
