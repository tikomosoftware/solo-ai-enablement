# AI開発支援 よくある失敗例

## 目的

このドキュメントは、AI開発支援ツールを使い始めたチームで起こりやすい失敗例をまとめたものです。

事故が起きてから学ぶのではなく、先によくあるパターンを知っておくことで、同じ失敗を避けやすくします。

## 失敗例1: 広いフォルダでClaude Codeを起動する

状況:

```text
cd C:\ProjectsDEV
claude
```

問題:

複数プロジェクトが見える状態で起動してしまい、Claude Codeが関係ないファイルまで参照する可能性があります。

対策:

対象リポジトリのプロジェクトルートで起動します。

```text
cd C:\ProjectsDEV\my-app
claude --permission-mode default
```

## 失敗例2: VS Codeのmulti-root workspaceで迷子になる

状況:

複数のプロジェクトを1つのVS Codeウィンドウに入れた状態でClaude Codeを使う。

問題:

どの `CLAUDE.md` や `.claude/settings.json` が対象か分かりにくくなります。AIが別プロジェクトを参照しているように見えることがあります。

対策:

最初は1つのVS Codeウィンドウに1つのプロジェクトだけを開きます。

## 失敗例3: AIが作ったコマンドを意味が分からないまま実行する

状況:

AIが提案したコマンドを、そのままコピーして実行する。

問題:

削除、履歴改変、環境変更、データ変更につながる可能性があります。

対策:

実行前にコマンドの意味を確認します。

```text
このコマンドが何をするか、影響範囲と戻し方を説明してください。
```

## 失敗例4: `.env` やトークンを貼る

状況:

エラー調査のために `.env` の中身やAPIキーを貼ってしまう。

問題:

秘密情報がAIサービスに送られる可能性があります。

対策:

値は伏せます。

```text
DATABASE_URL=<masked>
API_KEY=<masked>
```

## 失敗例5: AIが仕様を勝手に補完する

状況:

仕様が曖昧なまま実装を依頼する。

問題:

AIが一般的な仕様を想像して実装し、実際の実際の仕様とずれることがあります。

対策:

仕様が曖昧な場合は、実装せず質問させます。

```text
仕様が不明な点は推測せず、実装前に質問してください。
```

## 失敗例6: 依頼範囲外のリファクタリングが混ざる

状況:

小さなバグ修正を依頼したのに、周辺コードの整理まで行われる。

問題:

レビューが難しくなり、意図しない不具合が入りやすくなります。

対策:

依頼範囲を明確にします。

```text
依頼範囲外のリファクタリングや整形は行わないでください。
```

## 失敗例7: テストが通っていないのに完了扱いにする

状況:

AIが「修正しました」と言うが、テストやビルドを実行していない。

問題:

実際には壊れている可能性があります。

対策:

実行した確認と、実行できなかった確認を報告させます。

```text
実行したテスト、実行できなかったテスト、その理由を報告してください。
```

## 失敗例8: 存在しないAPIや古い書き方を使う

状況:

AIがライブラリの存在しない関数や古いAPIを使う。

問題:

ビルドエラーやランタイムエラーになります。

対策:

公式ドキュメント、型チェック、テストで確認します。

## 失敗例9: ログに機密情報を出す

状況:

AIがデバッグのためにリクエスト全体や環境変数をログ出力する。

問題:

個人情報、トークン、顧客情報がログに出る可能性があります。

対策:

ログ出力は最小限にし、値をマスクします。

## 失敗例10: 依存パッケージを勝手に追加する

状況:

AIが便利なライブラリを追加して実装する。

問題:

ライセンス、脆弱性、bundle size、保守性に影響します。

対策:

依存追加は事前承認にします。

## 失敗例11: force pushやresetを提案する

状況:

Gitの問題を解決するために、AIが `git reset` や `git push --force` を提案する。

問題:

履歴や他メンバーの作業を壊す可能性があります。

対策:

履歴改変系コマンドはAIに実行させません。

## 失敗例12: PRが大きくなりすぎる

状況:

AIが一度に複数の問題を直してしまう。

問題:

レビューが難しくなり、戻しづらくなります。

対策:

1つのPRは1つの目的に絞ります。

```text
この作業では、指定した不具合修正だけを行ってください。
他の改善は提案だけにしてください。
```

## まとめ

AI利用の失敗は、技術力不足よりも、作業範囲、権限、確認方法が曖昧なときに起こりやすいです。

よくある失敗をチームで共有し、harnessを少しずつ改善していきます。
