# 第4回 参加者向けメモ: 実プロジェクトへ広げる

このメモは、第4回「実プロジェクトへ広げる」の事前・事後に参加者へ共有するためのものです。

## 今日の目的

Claude Codeを実プロジェクトへ広げる前に、プロジェクトごとのルール、依頼文、FAQ、導入チェックを作ります。

一気に広げるのではなく、対象プロジェクトを1つ選び、小さなユースケースから始めます。

## 事前に確認しておくこと

自分のプロジェクトについて、分かる範囲で確認しておいてください。

- ローカルでの実行方法
- テスト方法
- レビュー方法
- 触ってよい範囲
- 触ってはいけない範囲
- 本番環境や本番DBに関係する注意点
- 秘密情報や環境変数の扱い
- 最初に試せそうな小さなユースケース

## 最初のユースケース候補

最初は、確認しやすい題材を選びます。

向いている題材:

- READMEや開発手順の補足
- 既存コードの説明
- テスト追加候補の洗い出し
- 小さな文言修正
- エラーや不具合の再現手順整理

避ける題材:

- 認証、権限、決済、DB移行
- 本番データ操作
- 大きな仕様変更
- 広いリファクタリング
- 削除や履歴操作

## 初回依頼文

```text
このプロジェクトで [やりたいこと] を試したいです。
まず変更は行わず、以下を整理してください。

1. 関連するファイルやフォルダ
2. 影響範囲
3. 実装または調査の方針
4. テストや動作確認の方法
5. リスク、不明点、今回やらない方がよいこと

触ってよい範囲は [範囲] です。
禁止操作は [禁止操作] です。
こちらが確認してから、次の作業に進んでください。
```

## 作業ログテンプレート

```text
何を頼んだか:

何を変更したか:

何を確認したか:

実行したテストや動作確認:

未確認のリスク:

次に見る人へのメモ:
```

## レビューに出す前の確認

- 差分を見た
- テストや動作確認をした
- AIの説明だけで判断していない
- 未確認のリスクを書いた
- プロジェクト固有ルールに合っている
- 相談が必要な範囲に入っていないか確認した

## 1週間後に見直すこと

実際に使ったあと、次を見直します。

- FAQに追加すべき質問
- 使いやすかった依頼文
- 分かりにくかったルール
- 相談が必要だった作業
- 危なそうだと感じた提案
- 次に試す小さなユースケース

実プロジェクトへの導入は、最初から完成形にしなくて大丈夫です。
小さく試して、現場に合わせて育てていきます。
