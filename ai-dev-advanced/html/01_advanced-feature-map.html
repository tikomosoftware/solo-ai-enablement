01. 高機能マップ

この章の目的

Claude Codeの高機能を、最初に全体像として整理します。

この章では各機能の細かい使い方には入りません。説明会後に「どの機能を詳しく知りたいか」を聞くためのメニュー表として使います。

扱うこと

  • Claude Codeの高機能には何があるか
  • どの機能がどんな困りごとに効くか
  • すぐ使いやすいものと、導入に注意が必要なものの違い
  • 詳細説明を別回に分けるための章立て

扱わないこと

  • 各機能の詳細な設定手順
  • 実プロジェクトへの導入作業
  • 外部サービスとの具体的な接続設定

説明会での使い方

最初にこの章を見せて、「今日は全部は説明しない」と伝えます。

そのうえで、参加者に次のような問いを投げます。

  • 毎回同じ依頼文を書いていて面倒な作業はあるか。
  • テスト、レビュー、PR説明などで自動化したい作業はあるか。
  • GitHub、Slack、Issue管理などとつなぎたい場面はあるか。
  • チームで共通化したい作業手順はあるか。

深掘り候補

  • 設定と権限設計
  • カスタムコマンド
  • Hooks
  • MCP連携
  • サブエージェント
  • SkillsとPlugins
  • Claude Security
  • Fable 5 / Mythos 5
  • 外部サービス連携
  • チーム自動化パターン

2026年6月時点で追加しておきたい観点

Claude Codeは、CLIだけで使う開発支援ツールというより、ターミナル、IDE、デスクトップ、Web、Slack、CI/CD、スケジュール実行まで広がるエージェント基盤になっています。

そのため、高機能編では次の観点も扱います。

| 観点 | 何を見るか | 導入時の注意 | |---|---|---| | Claude Codeの利用面 | Terminal、VS Code、JetBrains、Desktop、Web、Slack、CI/CD | どの面で使うかによって、ファイルアクセス、ログ、承認フローが変わる | | Claude Security | コードベースの脆弱性検出、検証、修正提案 | 人間のレビューと既存セキュリティプロセスへの接続が必要 | | Fable 5 | 一般利用向けのMythos-classモデル | 高性能だが、安全ガードやデータ保持条件を確認する | | Mythos 5 | 一部の信頼された組織向けに制限提供される高性能モデル | 通常のチーム導入資料では「利用前提」にしない | | safe mode | カスタマイズを無効化して起動するトラブルシュート用のモード | 問題切り分け用。通常運用の代替ではない | | managed settings | 組織・チームで強制する設定 | 管理者、例外申請、更新ルールを決める |

説明会では、最新機能を全部紹介しようとすると散らかります。まずは「このチームで使う可能性があるもの」と「今は存在だけ知っておけばよいもの」に分けます。
