05. MCP連携

この章の目的

Claude Codeを外部ツールやデータソースにつなぐMCP連携の考え方を扱います。

扱うこと

  • MCPで何を接続できるか
  • GitHub、Issue管理、監視、デザイン、社内データなどの候補
  • 接続先ごとの権限と情報管理
  • managed settingsによるMCP接続先の制御
  • 連携前に確認すること

扱わないこと

  • 未承認サービスへの接続
  • 機密情報や顧客情報への直接アクセス
  • 本番DBや本番環境への操作

説明会で扱う判断

MCPは要望が出やすい一方で、情報管理の確認が必要です。

具体的な接続先が決まってから、別回で扱うのが向いています。

最近の注意点

MCPは、便利さよりも先に「どのサーバーを許可するか」を決める必要があります。

Claude Codeでは、MCPサーバーやMCPツールに対して許可、確認、禁止のルールを設定できます。また、組織管理の設定で、許可するMCPサーバーや禁止するMCPサーバーを制御できます。

説明会では、次の順に確認します。

1. 接続先は業務上必要か。 2. 接続先のデータ分類は何か。 3. 読み取りだけか、書き込みや投稿もできるか。 4. 個人トークンで接続するのか、組織管理の接続にするのか。 5. ログ、監査、無効化方法があるか。 6. MCPサーバーをチーム全員に配布してよいか。

特に、GitHub、Slack、Jira、Google Drive、社内データベースのような接続は、AIの性能よりもアクセス権限の設計が先です。
