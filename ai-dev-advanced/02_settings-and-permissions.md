# 02. 設定と権限設計

## この章の目的

Claude Codeをチームで使う前に、どこまでAIに任せてよいかを設定とルールで整理します。

高機能を使う前の土台になる章です。

## 扱うこと

- `CLAUDE.md` の役割
- `.claude/settings.json` の役割
- managed settings、project settings、local settings、user settingsの分け方
- 許可、確認、禁止の分け方
- `default`、`plan`、`acceptEdits`、`auto`、`dontAsk`、`bypassPermissions` の使い分け
- チーム共有設定と個人設定の分け方
- 危険操作を止める考え方
- safe modeを使った切り分け

## 扱わないこと

- すべての設定項目の網羅
- 組織全体の正式ポリシー策定
- 本番環境や機密情報へのアクセス許可

## 説明会で扱う判断

高機能編の中では、最初に扱いやすい章です。

Hooks、MCP、サブエージェントなどを説明する前に、設定と権限の考え方を共有しておくと安全です。

## チームで最初に決めること

Claude Codeは、ファイルを読む、編集する、コマンドを実行する、外部ツールと接続する、といった操作ができます。高機能を使う前に、次を決めます。

- どのリポジトリで使ってよいか
- どのディレクトリを読ませてよいか
- どのファイルは読ませないか
- どのコマンドを許可するか
- どのコマンドは毎回確認するか
- どのコマンドは禁止するか
- 個人設定で変えてよい範囲はどこまでか
- 管理者が強制する設定は何か

## 権限モードの考え方

説明会では、権限モードを「便利さ」ではなく「失敗したときの影響」で説明します。

| モード | 説明会での扱い |
|---|---|
| `default` | 標準。最初はこの前提で説明する |
| `plan` | 調査と計画に寄せたいときに使う。初心者にも説明しやすい |
| `acceptEdits` | ファイル編集の確認を減らす。対象リポジトリと差分確認が前提 |
| `auto` | 自動承認に近い運用。研究プレビュー扱いとして、チーム標準にする前に検証する |
| `dontAsk` | 事前許可したもの以外を止めたいときに使う |
| `bypassPermissions` | 隔離環境向け。通常の開発PCや共有リポジトリでは説明会で推奨しない |

## safe modeの使いどころ

最近のClaude Codeでは、`--safe-mode` や `CLAUDE_CODE_SAFE_MODE` により、`CLAUDE.md`、plugins、skills、hooks、MCP serversなどのカスタマイズを無効化して起動できます。

これは、次のようなときに使います。

- どの設定が影響しているか分からない
- pluginやskillの更新後に挙動が変わった
- hookやMCP連携が原因か切り分けたい
- チーム共有設定ではなく、素のClaude Codeの挙動を確認したい

safe modeは恒久的な安全運用ではなく、原因切り分けのための入口です。通常運用では、権限、設定、レビュー、ログのルールを明示します。
