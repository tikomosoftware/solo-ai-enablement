# Claude Code高機能活用・自動化 インデックス

このフォルダは、Claude Codeの高機能や自動化を説明するための候補一覧です。

初回説明会や初心者向け資料では、ここにある内容をすべて説明しません。説明会後の質問、チームの成熟度、対象プロジェクトの状況に応じて、必要な章だけを選んで扱います。

## 作成状況について

**注意:** この資料は、現時点ではClaude Code高機能活用の構成案と検討メニューです。各章にはインデックスと簡単な要点を置いていますが、詳しい設定手順、実プロジェクトでの導入例、画面例、運用テンプレートはまだ作成中です。

完成済みの手順書ではなく、どの機能を今後深掘りするかを決めるための地図として扱ってください。

## 対象者

- Claude Codeの基本操作に慣れてきた開発者
- チームへAI開発支援を展開する担当者
- Hooks、MCP、サブエージェントなどの導入を検討する人
- プロジェクト単位でAI利用ルールや自動化を整備する人

## この資料の使い方

- 説明会では、まず「こういう高機能がある」という一覧として見せる。
- 参加者やチームから要望が出た章だけ、別回で詳しく説明する。
- すぐ使う機能と、まだ使わない機能を分けて考える。
- 導入前に、目的、権限、情報管理、レビュー方法を決める。

Claude Codeでできる高度なことを、設定、コマンド、Hooks、MCP、サブエージェント、Skills、Plugins、自動化に分けて俯瞰します。

説明会では、詳細に入る前の全体地図として使います。

### 2. 設定と権限設計

[02 設定と権限設計](./02_settings-and-permissions.md)

`CLAUDE.md`、`.claude/settings.json`、個人設定、プロジェクト設定、許可、確認、禁止の考え方を整理します。

高機能を使う前に、まず安全な境界を作るための章です。

### 3. カスタムコマンド

[03 カスタムコマンド](./03_custom-commands.md)

よく使う依頼や作業手順を、スラッシュコマンドとして再利用する考え方を扱います。

毎回同じ説明を手入力しているチームに向いています。

### 4. Hooks

[04 Hooks](./04_hooks.md)

Claude Codeの作業前後にコマンドを実行する仕組みを扱います。

formatter、テスト、通知、ログ保存などに使えますが、自動実行のリスクもあるため、導入判断を慎重に行います。

### 5. MCP連携

[05 MCP連携](./05_mcp.md)

GitHub、Issue管理、監視ツール、社内データ、デザインツールなど、外部サービスやデータソースとの連携を扱います。

情報管理とアクセス権限の確認が必要なため、説明会では要望がある場合だけ詳しく扱います。

### 6. サブエージェント

[06 サブエージェント](./06_subagents.md)

調査、実装、レビュー、テスト、ドキュメント作成など、役割を分けて作業する考え方を扱います。

並行作業や専門分担に便利ですが、責任範囲と変更範囲を明確にしてから使います。

### 7. SkillsとPlugins

[07 SkillsとPlugins](./07_skills-and-plugins.md)

チーム固有の作業手順、レビュー観点、ドキュメント作成手順などを再利用可能な形にする考え方を扱います。

まずは手作業の運用を固め、繰り返し使うものが見えてから整備します。

### 8. 外部サービス連携

[08 外部サービス連携](./08_external-integrations.md)

GitHub、Slack、カレンダー、メール、ドキュメント管理など、チームに影響するサービスとの連携を扱います。

通知、投稿、PR操作、予定変更などが発生するため、権限と承認フローを先に決めます。

### 9. チーム自動化パターン

[09 チーム自動化パターン](./09_team-automation-patterns.md)

レビュー補助、テスト実行、PR説明作成、リリースノート作成、作業ログ整理など、チームで使いやすい自動化パターンを整理します。

個別機能の説明ではなく、実務フローとしてどう組み合わせるかを扱います。

### 10. 導入判断チェックリスト

[10 導入判断チェックリスト](./10_adoption-checklist.md)

高機能をチームで使う前に確認する項目をまとめます。

説明会後に「この機能を使いたい」と要望が出たとき、導入可否を判断するための入口として使います。

## 説明会での扱い方

最初の説明会では、次のように扱います。

1. 高機能があることだけ紹介する。
2. 今日すぐ使うものではないと伝える。
3. 興味がある機能や困っている作業を聞く。
4. 要望が多い章から、別回で詳しく扱う。

## 最初に深掘りしやすい章

チーム開発で要望が出やすいのは、次の章です。

- 設定と権限設計
- カスタムコマンド
- Hooks
- MCP連携
- サブエージェント
- チーム自動化パターン

ただし、最初に扱う章は機能の派手さではなく、チームの困りごとから決めます。
