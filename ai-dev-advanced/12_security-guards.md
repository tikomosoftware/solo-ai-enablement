# 12. セキュリティガードと導入時の注意点

作成日: 2026-06-10

最終確認日: 2026-06-10

## この章の目的

Claude CodeやClaude関連機能をチームに入れるときの、安全ガードと限界を整理します。

ここでいうセキュリティガードは、単一の機能名ではありません。Claude Codeの権限、safe mode、managed settings、MCP制御、Claude Security、Fable 5の安全ガードなどをまとめた運用上の考え方です。

## 基本方針

安全機能があることと、チームで安全に使えることは別です。

説明会では、次のように伝えます。

- AIの提案は、レビュー前提で使う。
- 権限設定は、プロンプトより強い境界として扱う。
- MCP、hooks、plugins、skillsは、便利さより先に無効化方法を確認する。
- セキュリティレビューは、Claude Securityだけに任せない。
- 高性能モデルほど、データ保持、ログ、フォールバック、安全ガードの条件を確認する。

## Claude Code側のガード

Claude Codeでは、次のようなガードを組み合わせます。

| ガード | 役割 | 注意点 |
|---|---|---|
| 権限ルール | Bash、Read、Edit、WebFetch、MCP、Agentなどの許可・確認・禁止を決める | 指示文ではなく設定で止める |
| permission mode | 権限確認の粒度を変える | `auto` や `bypassPermissions` は慎重に扱う |
| managed settings | 組織やチームで設定を強制する | 管理者と更新手順が必要 |
| safe mode | カスタマイズを無効化して切り分ける | 通常運用の代替にはしない |
| sandbox | OSレベルでアクセス範囲を制限する | ツールや環境によって使える範囲が変わる |
| hooks | 実行前後に検査や記録を入れる | hook自体が危険操作をしないようにする |

## Fable 5の安全ガード

Fable 5は、一般利用向けに提供されるMythos-classモデルです。

安全ガードにより、サイバーセキュリティ、バイオ、化学、蒸留に関わる一部のリクエストでは、Fable 5が直接回答せず、別モデルにフォールバックすることがあります。

チーム説明でのポイント:

- ガードがあるから何でも聞いてよい、ではない。
- フォールバックが起きる可能性を利用者に説明する。
- サイバー防御目的でも、攻撃手順や悪用可能な詳細に踏み込む依頼は慎重に扱う。
- 高性能モデルを使う場合、データ保持やログの条件を確認する。

## Mythos 5の扱い

Mythos 5は、Fable 5と同じ基盤のモデルで、一部の安全ガードが外された形で限定提供されます。

通常の開発チーム向け資料では、Mythos 5を「使える前提」にしません。

説明会では、次の程度に留めます。

- Mythos 5は、サイバー防御や研究用途の信頼アクセス向けに制限提供される。
- 一般的な開発者教育では、Fable 5や通常のClaude Code利用を前提にする。
- Mythos 5相当の能力が必要な場合は、個別の承認、契約、データ管理、監査が必要になる。

## Claude Securityの扱い

Claude Securityは、コードベースをスキャンし、脆弱性を検出し、検証し、修正案を提示する機能です。

使う価値がある場面:

- 大きなコードベースのセキュリティレビューを補助したい
- 複数ファイルをまたぐデータフローを確認したい
- 既存ツールで拾いにくいロジック上の弱点を探したい
- 修正案まで含めてレビューしたい

導入時の注意:

- 結果は人間が確認する。
- 修正案はテスト、レビュー、既存設計との整合を確認する。
- 既存のセキュリティツールを置き換える前提にしない。
- スキャン対象、通知先、チケット化、監査ログを決める。
- 誤検知、判断保留、リスク受容を記録する。

## MCP、plugins、skillsのガード

MCP、plugins、skillsは、Claude Codeの能力を広げます。広げた分だけ、リスクも増えます。

導入前に確認すること:

- 誰が作ったものか
- どのデータにアクセスするか
- 書き込みや投稿ができるか
- 更新時にレビューされるか
- 使わなくなったときに無効化できるか
- チーム全員に配ってよいか

外部pluginや外部MCPサーバーは、便利でも、最初から標準導入しない方が安全です。まず小さい範囲で試し、必要なら管理者が配布方法を決めます。

## 説明会で使う短い言い方

> Claude Codeには安全機能がありますが、安全機能は万能ではありません。  
> チームで使うときは、権限、接続先、ログ、レビュー、停止方法を先に決めます。  
> AIには下書き、調査、候補提示を任せ、最終判断は人間が行います。

## 最低限の導入ルール

- 初期状態は `default` または `plan` を前提にする。
- `bypassPermissions` は通常PCでは使わない。
- MCP、hooks、plugins、skillsは、導入前にレビューする。
- Claude Securityの修正案は、そのまま取り込まない。
- Fable 5 / Mythos 5のような新モデルは、提供範囲とデータ条件を確認してから使う。
- 問題が起きたら safe mode で切り分ける。
- すべての変更は、差分、テスト、レビューを通す。
