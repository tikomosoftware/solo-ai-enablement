# 11. 最近のClaude関連アップデート

作成日: 2026-06-10

最終確認日: 2026-06-10

## この章の目的

Claude Code高機能編を説明するときに、最近追加・強化されたClaude関連機能を整理します。

この章は、細かい操作手順ではなく、「いま何が増えていて、チーム導入時に何を気にするべきか」を共有するための更新メモです。

## まず押さえる全体像

Claude Codeは、ターミナルで動く開発支援CLIから、IDE、デスクトップ、Web、Slack、CI/CD、スケジュール実行、MCP、skills、plugins、subagentsを含む開発エージェント基盤に広がっています。

そのため、高機能編では「Claude Codeをどう使うか」だけでなく、次の観点が必要です。

- どの利用面を許可するか
- どのモデルを使うか
- どの外部サービスに接続するか
- どの設定をチームで管理するか
- どの作業に人間の承認を残すか

## Fable 5 / Mythos 5

公式名は `Claude Fable 5` と `Claude Mythos 5` です。

Fable 5は、Mythos-classの能力を一般利用向けに提供するモデルです。ソフトウェアエンジニアリング、長い作業、知識作業、画像理解などで高い能力がある一方、サイバーセキュリティ、バイオ、化学、蒸留に関わる一部のリクエストでは安全ガードが働き、別モデルにフォールバックすることがあります。

Mythos 5は、Fable 5と同じ基盤のモデルですが、一部の安全ガードが外された形で、主に信頼されたサイバー防御組織や研究者向けに限定提供されます。通常のチーム向け説明では、Mythos 5を利用前提にしません。

説明会での言い方:

- Fable 5は「より長い作業や複雑な開発作業に強いモデル」として紹介する。
- Mythos 5は「一般チームがすぐ使う機能」ではなく、制限提供される高リスク領域向けモデルとして扱う。
- 新モデルを使う前に、プラン、提供範囲、データ保持、社内承認を確認する。

## Claude Security

Claude Securityは、コードベースをスキャンし、脆弱性を見つけ、検証し、修正案を提示するための機能です。

従来のパターンマッチ型のスキャナとは違い、複数ファイルをまたいだデータフローや文脈を見て、複雑な脆弱性を探すことを狙っています。

ただし、説明会では「セキュリティ担当者を置き換える機能」と説明しません。

チーム導入時の確認:

- 対象リポジトリをどこまでにするか
- スキャン結果を誰が確認するか
- 修正案をそのまま適用せず、誰がレビューするか
- 既存のSAST、DAST、依存関係スキャン、脆弱性管理とどう併用するか
- Slack、Jira、チケット管理に連携する場合、誰が通知先と権限を管理するか
- 誤検知や判断保留をどう記録するか

## safe mode

Claude Codeには、カスタマイズを無効化して起動するsafe modeがあります。

無効化される対象の例:

- `CLAUDE.md`
- plugins
- skills
- hooks
- MCP servers

safe modeは、次のような切り分けに使います。

- 最近追加したskillの影響を外したい
- pluginやMCP接続が原因か確認したい
- hookが意図せず動いている可能性がある
- チーム共有設定ではなく、素の状態で挙動を確認したい

safe modeは、通常運用の安全策そのものではありません。恒久的な安全策は、権限設計、managed settings、レビュー、ログ、停止手順で作ります。

## managed settingsと組織管理

Claude Codeは、個人設定だけでなく、組織やチームが管理する設定を使えます。

最近の変更では、MCPサーバーの許可・禁止、バージョン制約、権限モード制限など、管理者が安全側に寄せるための設定が重要になっています。

説明会で扱うべき点:

- 個人が自由に変えてよい設定
- プロジェクトで共有する設定
- 管理者が強制する設定
- MCPやpluginの接続先制限
- Claude Codeの最低・最高バージョン
- `auto` や `bypassPermissions` を許可するか

## skills / plugins / workflows

Claude Codeでは、skillsやpluginsによって、作業手順やツール連携をパッケージ化できます。

説明会でのポイントは、「便利そうだから入れる」ではなく、「繰り返し使う手順を、レビュー可能な形にする」です。

導入前に決めること:

- 誰が作るか
- 誰がレビューするか
- どのリポジトリで管理するか
- どのバージョンを使うか
- 問題が起きたときに無効化できるか
- 外部pluginを使う場合、配布元を信頼できるか

## 説明会での優先順位

全部を一度に説明すると散らかるため、次の順で扱います。

1. 設定と権限設計
2. Claude Securityなど、チームの具体的な困りごとに近い機能
3. MCP、skills、plugins、hooks
4. サブエージェント、複数セッション、スケジュール実行
5. Fable 5 / Mythos 5などのモデル更新

モデル名から入ると、使い方より話題性に引っ張られます。説明会では、「このチームのどの作業を安全に楽にするか」から入る方がよいです。
