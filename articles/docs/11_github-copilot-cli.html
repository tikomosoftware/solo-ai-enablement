11. GitHub Copilot CLIの使い方

この記事の目的

この記事では、GitHub CopilotをCLI、つまりターミナル上で使う基本を説明します。

VS Codeの画面で使うCopilotとは違い、CLIではコマンド実行、エラー調査、作業手順の相談、リポジトリ内の変更作業などをターミナルから依頼できます。普段からPowerShell、Git Bash、ターミナル、WSLを使う人に向いています。

Copilot CLIでできること

Copilot CLIは、ターミナル上でAIに作業を相談できる道具です。

代表的な使い方は次のとおりです。

  • コマンドの意味を説明してもらう
  • やりたい操作に合うコマンドを提案してもらう
  • エラー内容を貼って原因を相談する
  • Git操作の手順を確認する
  • リポジトリ内のファイルを見ながら変更方針を相談する
  • 小さな修正や調査を依頼する

公式ドキュメントでは、組織でCopilotを利用している場合、Copilot CLIの利用ポリシーが組織設定で有効になっている必要があると説明されています。所属組織アカウントで使えない場合は、契約や組織ポリシーを確認します。

最初に確認すること

使い始める前に、次を確認します。

  • GitHub Copilotの利用権限があるか
  • GitHub CLIまたはCopilot CLIを利用できる環境か
  • 所属組織のGitHub OrganizationでCopilot CLIが許可されているか
  • 仕事で扱うコードや機密情報をAIに渡してよい範囲が決まっているか

所属組織のリポジトリで使う場合、個人判断で自由に使うのではなく、チームルールに従うことが重要です。

基本的な使い方

まずは、リポジトリのルートディレクトリでCopilot CLIを起動します。

copilot

実際のコマンド名や起動方法は、所属組織の導入方法やGitHub側の最新仕様によって変わる場合があります。使えない場合は、GitHub公式ドキュメントの「GitHub Copilot CLI」を確認します。

CLIを開いたら、自然文で依頼できます。

このリポジトリの構成を調べて、READMEに書くべき概要を提案してください。
npm run build が失敗しました。エラーの原因候補を整理してください。
この変更をコミットする前に、差分のリスクを確認してください。

VS Codeとの接続

GitHub Copilot CLIは、VS Codeで開いているワークスペースと接続できる場合があります。

公式ドキュメントでは、Copilot CLIを起動した作業ディレクトリが、信頼済みモードで開いているVS Codeワークスペースと一致しているかを確認すると説明されています。接続できると、CLI側の作業とVS Code側の編集体験を組み合わせやすくなります。

うまく接続されない場合は、次を確認します。

  • VS Codeで同じフォルダを開いているか
  • ワークスペースが信頼済みになっているか
  • ターミナルの作業ディレクトリがプロジェクトルートか
  • Copilot CLIとVS Code拡張が最新か

使いどころ

Copilot CLIは、次のような場面で使いやすいです。

  • コマンドライン作業が多い
  • エラー調査をターミナル上で完結したい
  • CI、ビルド、テスト、Git操作の相談をしたい
  • VS Codeを開かずに軽く確認したい
  • 自動化スクリプトやシェル操作の相談をしたい

逆に、コードを見ながら細かく編集する作業は、VS Code上のCopilotのほうが向いていることがあります。

注意点

Copilot CLIに依頼するときは、次の点に注意します。

  • 提案されたコマンドを意味がわからないまま実行しない
  • 削除、リセット、上書き、force pushなどの危険な操作は必ず止まって確認する
  • 機密情報、トークン、パスワード、顧客情報を貼らない
  • AIの説明を正解扱いせず、必要に応じて公式情報で確認する
  • 所属組織のGitHub Organizationの利用ルールに従う

特にターミナルは、コマンドひとつでファイル削除や履歴変更ができてしまいます。AIに作らせたコマンドほど、実行前に意味を確認する習慣が必要です。

この章のまとめ

GitHub Copilot CLIは、ターミナル上で開発作業を相談できるAIツールです。

コマンド、エラー、Git操作、ビルド、テストの相談に向いています。一方で、危険なコマンドをそのまま実行しないこと、機密情報を入力しないことが重要です。
