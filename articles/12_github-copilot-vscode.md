# 12. GitHub CopilotをVS Codeで使う

## この記事の目的

この記事では、GitHub CopilotをVS Codeで使うときの基本を説明します。

VS CodeでのCopilotは、単なるコード補完だけではありません。現在は、コード補完、チャット、Ask、Edit、Agent、カスタムエージェント、プロンプトファイル、MCPなど、複数の機能を組み合わせて使う形になっています。

## まず押さえる使い方

VS CodeでCopilotを使うとき、最初に押さえるべき使い方は次の4つです。

- インライン補完
- Ask
- Edit
- Agent

インライン補完は、コードを書いている途中に次の候補を提案してくれる機能です。短い関数、繰り返し処理、型定義、テストコードの補完などに向いています。

Askは、コードやエラーについて質問する使い方です。基本的には相談や説明向けです。

Editは、範囲やファイルを指定して変更を依頼する使い方です。比較的スコープが明確な修正に向いています。

Agentは、Copilotが作業手順を考え、ファイルを探し、編集し、必要に応じてコマンド実行まで含めて進める使い方です。便利ですが、影響範囲が広くなりやすいので、レビュー前提で使います。

## Askの使い方

Askは、まず安全に試しやすい使い方です。

例:

```text
この関数が何をしているか、初心者向けに説明してください。
```

```text
このエラーの原因候補を3つ挙げてください。
```

```text
この実装のリスクや改善点をレビューしてください。
```

Askでは基本的に、いきなりファイル変更を任せるより、理解、調査、確認に使うのが向いています。

## Editの使い方

Editは、変更したい範囲がある程度はっきりしているときに使います。

例:

```text
この関数に入力値チェックを追加してください。
既存の戻り値の形式は変えないでください。
```

```text
このコンポーネントの表示文言を組織内向けの表現に直してください。
レイアウトは変更しないでください。
```

Editを使うときは、変更範囲、守る条件、変更してはいけないことを明確に伝えると事故が減ります。

## Agentの使い方

Agentは、複数ファイルにまたがる調査や修正に向いています。

例:

```text
ログイン画面のバリデーションエラー表示を改善してください。
まず関連ファイルを調査し、変更方針を説明してから実装してください。
```

```text
このIssueに対応してください。
既存テストを確認し、必要ならテストも追加してください。
```

Agentは自律的に作業できるぶん、次の指示を入れると安全です。

- まず調査してから方針を説明する
- 変更範囲を限定する
- 既存の設計や命名に合わせる
- テストやビルドで確認する
- 危険なGit操作や削除はしない

## カスタムエージェント

VS Codeでは、用途に合わせたカスタムエージェントを作れます。

たとえば、次のような役割を作れます。

- 設計レビュー担当
- セキュリティレビュー担当
- テスト作成担当
- 実装前の計画担当
- ドキュメント整備担当

公式ドキュメントでは、カスタムエージェントは `.agent.md` 形式のMarkdownファイルで定義でき、ワークスペース内に置くことでチーム共有できると説明されています。以前のカスタムチャットモードは、現在はカスタムエージェントという呼び方に変わっています。

## チームで使うときの基本設定

チーム利用では、Copilotに毎回同じ前提を伝えるためのファイルを置くと便利です。

代表的には次のようなファイルです。

- `.github/copilot-instructions.md`
- `AGENTS.md`
- 目的別のプロンプトファイル
- `.github/agents/*.agent.md`

ここに、コード規約、命名ルール、テスト方針、禁止事項、レビュー観点などを書いておくと、メンバーごとの依頼のばらつきを減らせます。

## 注意点

VS Code上のCopilotは便利ですが、次の点に注意します。

- Agentに任せる前に作業範囲を明確にする
- 変更後の差分を必ず確認する
- 生成コードをテストする
- セキュリティ、認証、課金、権限まわりは特に慎重に見る
- AIが作ったコードを理解しないままマージしない
- 機密情報をチャットに貼らない

## この章のまとめ

VS CodeでのGitHub Copilotは、補完、Ask、Edit、Agentを使い分けるのが基本です。

最初はAskで理解や調査に使い、慣れてきたらEditで小さな修正を依頼し、さらにAgentで複数ファイルの作業を任せる、という段階的な使い方が安全です。
