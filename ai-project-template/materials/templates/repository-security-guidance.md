# このリポジトリのセキュリティガイダンス

## このテンプレートの目的

このファイルは、対象リポジトリ固有のセキュリティ観点をClaude Codeに伝えるためのテンプレートです。

実プロジェクトに導入するときは、このファイルをそのまま使うのではなく、対象リポジトリの技術、データ、認証方式、運用ルールに合わせて編集してください。

コピー先の例:

```text
.claude/policies/security.md
```

コピー後は、`CLAUDE.md` からこのファイルを参照させます。

## セキュリティガイダンス

- ユーザーデータを読み書きするAPIでは、必ず認証チェックを行うこと。
- 管理者向け機能では、必ず管理者権限チェックを行うこと。
- アクセストークン、リフレッシュトークン、APIキー、パスワード、個人情報をログに出さないこと。
- マルチテナントのデータ取得では、必ず `organization_id` または `tenant_id` で絞り込むこと。
- `dangerouslySetInnerHTML` は原則使わない。使う場合はサニタイズと理由を明記すること。
- ユーザー入力のURLへサーバー側から直接アクセスしない。必要な場合はallowlistで検証すること。
- シークレットをソースコード、`.env.example`、ログ、テストデータに含めないこと。

## AIに依頼するときの確認観点

実装、レビュー、修正案の作成では、次を確認してください。

- 認証が必要な処理で、未認証アクセスができないか。
- 認可が必要な処理で、別ユーザーや別組織のデータへアクセスできないか。
- 管理者向け処理が、一般ユーザーから呼び出せないか。
- ログ、エラー、監査記録に秘密情報や個人情報が出ないか。
- ユーザー入力がHTML、SQL、コマンド、URL、ファイルパスとして危険に扱われていないか。
- テストデータ、サンプル、ドキュメントに実在の秘密情報が混ざっていないか。

## このテンプレートを編集するときの注意

- このリストは最低限のたたき台です。
- プロジェクトで使っているフレームワーク、認証基盤、DB、ログ基盤に合わせて項目を追加してください。
- セキュリティ判断の最終責任は人間が持ちます。
- AIが「問題なさそう」と言っても、認証、認可、ログ、シークレット、マルチテナント境界は人間が確認してください。
