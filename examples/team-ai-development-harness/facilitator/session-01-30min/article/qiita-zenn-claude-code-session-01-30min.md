# Claude Codeをチームで安全に試す第1回30分説明会の資料を作った話

## はじめに

Claude Codeをチームで使い始めるとき、いきなり実装を任せるのは少し危険です。

最初は、対象リポジトリの場所を確認し、ルールと権限を確認し、コードを変更せずにプロジェクトを説明してもらうところから始めるのがよいと考えました。

そこで、第1回の30分説明会資料を作りました。

## 1. 第1回のゴールは「実装」ではなく「安全に触る」

第1回では、Claude Codeにいきなり実装させません。

扱うのは、次のような安全な初回操作です。

- 対象リポジトリのルートで起動する
- VS Codeは1プロジェクト1ウィンドウにする
- `plan` modeで起動する
- `/memory` でルールを確認する
- `/permissions` で権限設定を確認する
- 変更なしでリポジトリ構成を調査してもらう

最初の依頼例も、実装ではなく調査にしています。

```text
まずこのリポジトリの構成を調査してください。
変更はまだ行わず、主要なフォルダ、実行方法、
テスト方法、注意点を整理してください。
```

この使い方だけでも、初回の導入としては十分価値があります。

## 2. 第0回のおさらいは1枚に圧縮した

第0回では、AIツールを使うときの基本を扱っています。

そのため、第1回では次のような内容を何枚も使って説明し直すのではなく、「第0回のおさらい」として1枚にまとめました。

- 相談は小さく区切る
- AIの提案は確認する
- 危ない操作は避ける
- 分からないことは聞く

第1回の本筋は、Claude Codeの起動場所、ルール確認、権限確認、プロジェクト解析の依頼です。

## 3. 実演に入りやすいスライド構成にした

説明会では、スライドを読むだけではなく、実際にサンプルプロジェクトを使って画面を見せます。

そのため、スライドには「ここから実演に入ります」という切り替え用のページを入れました。

```text
ここから実演に入ります

サンプルプロジェクトを使って、
起動場所、ルール確認、権限確認、
プロジェクト解析の依頼までを一緒に見ます。
```

このスライドがあると、説明パートから画面共有・ターミナル操作へ自然に切り替えやすくなります。

また、`今日のアジェンダ` / `今日のゴール` のような表現は少し重複して見えたため、次のようにしました。

- `今日のアジェンダ` → `本日の流れ`
- `今日のゴール` → `この回の目的`

## 4. 説明後の行動は「やること」ではなく「やってみること」にした

説明会後の案内も、強制感が出ないように調整しました。

最初は `説明会後にやること` のような表現でしたが、少し宿題感があります。

そこで、見出しを次のように変えました。

```text
次にやってみること
```

内容は、次のような軽い行動にしています。

- `docs/start-guide.md` を見ながら初回セットアップ
- `docs/first-exercise.md` の最初の課題をやってみる
- 分からないことや不安だったことを共有する

「やらなければならない」ではなく、「まず小さく使ってみる」雰囲気を大事にしました。

## 5. 困ったときの相談と共有を分けた

最初は、困ったときの資料案内と共有してほしいことを1枚にまとめていました。

しかし、それだと情報が詰まりすぎて、伝えたいことが見えにくくなります。

そこで、最後の部分は2枚に分けました。

1枚目:

```text
困ったら気軽に聞く
```

ここでは、説明会の担当者、プロジェクトのリード、チームで決めた相談先など、まず人に聞いてよいことを伝えます。

2枚目:

```text
小さなつまずきも共有する
```

ここでは、次のようなものを共有してほしいとしています。

- 危なそうな提案
- 分かりにくかったこと
- 自分がつまずいたところ
- 便利だった使い方

最後に、次の一文を入れました。

```text
小さな失敗や気づきも、あとでチームの資産になります。
```

個人の失敗ではなく、チームで安全に使うための材料として扱う、というメッセージです。

## 6. 第2回以降を見据えて資料をフォルダ分けした

当初、第1回資料は `facilitator/` 直下に置いていました。

しかし、今後第2回・第3回を作っていくなら、説明会ごとにフォルダを分けた方が見通しがよくなります。

そこで、第1回資料は次のフォルダにまとめました。

```text
examples/team-ai-development-harness/facilitator/session-01-30min/
```

今後は、たとえば次のように増やせます。

```text
facilitator/
  session-00-ai-basics/
  session-01-30min/
  session-02-...
  session-03-...
```

`facilitator/README.md` や `STRUCTURE.md` も、この構成に合わせて更新しました。

## まとめ

第1回資料は、Claude Codeをいきなり実装に使うのではなく、安全に触るための入口として作りました。

ポイントは、次の3つです。

- 最初は実装ではなく、変更なしの調査から始める
- 危険な操作や秘密情報の扱いを最初に避ける
- 困ったことや小さなつまずきをチームで共有する

第0回でAIツール全般の見取り図をそろえ、第1回でClaude Codeを安全に試す。

この2段階に分けることで、AIに慣れていない人も参加しやすい説明会にできると感じました。
