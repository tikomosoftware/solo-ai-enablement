# 第1回 デモ手順: 変更前に調べてから文言を直す

## 目的

AIにすぐ修正させるのではなく、最初に構成、対象ファイル、変更方針を整理させる練習をします。

## 登壇者の流れ

1. VS Codeで `01-docs-copy-fix` フォルダを開く
2. Claude Codeパネルを開く
3. AIに「まだ変更しないで」と明示して調査を依頼する
4. 触る予定のファイルと変更方針を確認する
5. `docs/usage.md` だけに絞って修正を依頼する
6. VS Codeの差分表示で、文言だけが変わったことを確認する
7. Markdownプレビューで読みやすくなったか確認する

## 最初に使う依頼文

```text
このサンプルプロジェクトで、利用手順の説明を少し分かりやすくしたいです。
まだ変更は行わず、まず以下を整理してください。

1. プロジェクト構成
2. 修正候補になりそうなファイル
3. 小さく直す場合の方針
4. 変更後の確認方法
5. 今回触らない方がよい範囲
```

## 実装を依頼する文

```text
方針は問題ありません。
今回は docs/usage.md だけを対象にして、初めて使う人にも分かるように文言を少し補足してください。
修正後に差分と確認方法を説明してください。
```

## 確認ポイント

- `docs/usage.md` 以外を触っていないか
- 文章量が増えすぎていないか
- 手順の意味が変わっていないか
- AIが「確認方法」を説明できているか
- VS Code上で変更ファイルと差分を見られたか

## 参加者の練習課題

`docs/faq.md` の「保存されない場合」の回答を、初めて読む人に分かりやすい表現へ少しだけ直してください。
