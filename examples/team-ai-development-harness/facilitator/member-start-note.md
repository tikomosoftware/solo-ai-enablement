# Claude Codeをチームで試すためのはじめ方メモ

このメモは、Claude Codeをチームで試す前に「最初に何をすればいいか」だけを確認するための入口です。

ここでは、詳しい使い方や用語を全部理解する必要はありません。正しい場所で起動すること、最初は変更なしで試すこと、困ったときにどこを見るかが分かれば十分です。

Claude Codeは、開発作業を手伝ってくれるAIツールです。まずはコードを書かせるのではなく、プロジェクトの中身を説明してもらうところから試します。

このメモを読んだ後のステップ:

1. `docs/start-guide.md` を見ながら初回セットアップを行う
2. `docs/first-exercise.md` の最初の課題を試す
3. 分からないことや不安だったことを共有する

途中で分からない言葉や操作が出てきた場合は、無理に進めず、その時点で質問してください。

## このメモについて

Claude Codeをいきなり本格導入するのではなく、まずは安全に触ってみるための入口を用意しました。

最初から大きな実装を任せる必要はありません。まずは、プロジェクトの構成を調べてもらう、既存コードを説明してもらう、レビュー観点を出してもらうなど、変更を伴わない使い方から試していきます。

分からない用語が出てきた場合は、あとで `docs/glossary.md` を見れば大丈夫です。

## まず試してみること

対象リポジトリで、次を試してみてください。

ここでいう対象リポジトリは、今回Claude Codeを試したいプロジェクトのフォルダです。

1. VS Codeで対象リポジトリのプロジェクトルートを開く
2. VS Codeの統合ターミナルを開く
3. Claude Codeを `plan` modeで起動する
4. `/memory` で `CLAUDE.md` が読み込まれているか確認する
5. `/permissions` で権限設定が効いているか確認する
6. 変更なしでリポジトリ構成を調査してもらう

補足:

- プロジェクトルート: VS Codeで「フォルダーを開く」ときに選ぶ一番上のフォルダ
- 統合ターミナル: VS Codeの中で開くターミナル画面
- `plan` mode: まず調査や方針整理だけをしてもらうための起動方法
- `/memory`: Claude Codeが読み込んでいるルールを確認するコマンド
- `/permissions`: Claude Codeに許可・禁止されている操作を確認するコマンド

起動例:

```text
claude --permission-mode plan
```

最初の依頼例:

```text
まずこのリポジトリの構成を調査してください。
変更はまだ行わず、主要なフォルダ、実行方法、テスト方法、注意点を整理してください。
```

## 最初は避けたいこと

慣れるまでは、取り消しにくい操作や影響範囲が大きい作業はClaude Codeに任せない方針で進めます。

- ファイル削除
- ディレクトリ削除
- ファイルの大量移動、リネーム
- `git reset`
- `git clean`
- `git rebase`
- `git push --force`
- `git push --force-with-lease`
- 本番環境への操作
- 本番DBへの操作
- `.env`、APIキー、トークン、秘密鍵などの入力
- 大きなリファクタリング

Claude Codeがこれらを提案した場合は、実行せずに一度相談してください。

## 最初の課題

最初の課題は `docs/first-exercise.md` にあります。

この課題では、コード変更やコミットは行いません。

目安としては、15〜30分くらいで試せる内容です。

ゴール:

- Claude Codeを正しい場所で起動できる
- `/memory` と `/permissions` を確認できる
- 変更なしでリポジトリ調査ができる
- 便利だった点、不安だった点を共有できる

## 困ったとき

分からないこと、怖いと思ったこと、便利だった使い方があれば共有してください。

```text
共有先: TODO
相談先: TODO
```

共有してほしい例:

- Claude Codeが危なそうなコマンドを提案した
- `.env` や秘密情報を読もうとした
- 依頼していないファイルを変更しようとした
- 使い方が分からなかった
- 便利だった使い方があった

## 補足: 慣れてきた後の使い方

最初の課題が終わって、少し慣れてきたら、調査、説明、レビュー補助を中心に試してみるのはどうでしょう。

小さな修正に使う場合も、いきなり実装を任せるのではなく、まず調査、方針確認、実装、差分確認の順番で進めると安全です。

AIを使った変更でも、通常のレビュー、テスト、承認フローは省略しない形にしておくと安心です。

まずは、冒頭のステップに沿って、安全に触ってみるところから始めましょう。
