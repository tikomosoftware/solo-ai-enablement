## 0:03-0:08 Harnessの考え方

AIは便利ですが、チーム開発では自由に使えばよいわけではありません。

AIに作業させる前に、前提、権限、作業手順、確認方法を整える必要があります。これをこの資料ではharnessと呼んでいます。

大きく4つです。

- Context: AIに渡す前提
- Guardrails: 危険操作を止める仕組み
- Workflow: 作業の進め方
- Verification: 確認方法

今回の資料では、`CLAUDE.md`、`.claude/settings.json`、`policies/`、`checklists/` などでこれを実現します。

## 0:08-0:14 起動場所とVS Code注意点

Claude Codeは、対象リポジトリのプロジェクトルートで起動してください。

プロジェクトルートは、VS Codeで「フォルダーを開く」ときに選ぶ一番上のフォルダです。

よい例:

```text
cd C:\ProjectsDEV\my-app
claude --permission-mode default
```

避ける例:

```text
cd C:\
claude
```

```text
cd C:\ProjectsDEV
claude
```

VS Codeでは、最初は1つのウィンドウに1つのプロジェクトだけを開いてください。

multi-root workspaceは便利ですが、最初は作業対象が曖昧になりやすいので避けます。

## 0:14-0:20 最低限の禁止事項

最初に守ってほしいことは、これです。

- `.env`、APIキー、トークン、秘密鍵をAIに渡さない。
- 削除、reset、clean、rebase、force pushはAIに実行させない。
- 本番環境や本番DBに影響する操作はAIに実行させない。
- AIが作ったコードを確認なしでコミットしない。
- 変更範囲が大きい作業は、まず調査だけ依頼する。

AIが危険な操作を提案した場合は、実行せずに相談してください。

## 0:20-0:24 ツールの使い分け

ざっくり使い分けはこうです。

- コード補完や小さな修正: GitHub Copilot
- ターミナルやコマンド相談: Copilot CLI または Claude Code
- リポジトリ調査や複数ファイル修正: Claude Code
- PR前レビューやテスト観点整理: Claude Code

最初は、Claude Codeにいきなり実装させず、調査や説明から使ってください。
