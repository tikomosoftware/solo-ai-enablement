# 第1回 30分説明会 台本たたき台

## この台本の目的

この台本は、Claude Codeをチームで初めて試すための第1回説明会用です。

第1回では、Claude Codeの全機能を説明するのではなく、「安全に起動して、変更なしでプロジェクトを説明してもらう」ところまでを扱います。

初回のゴールは、Claude Codeにコードを書かせることではありません。

**まずは、サンプルプロジェクトをClaude Codeに説明してもらうところまでを実演します。**

## 事前に用意するもの

説明者は、事前にサンプルプロジェクトを1つ用意しておきます。

例:

```text
sample-todo-app/
  .git/
  CLAUDE.md
  .claude/
    settings.json
  README.md
  package.json
  src/
  tests/
```

サンプルプロジェクトは、本番コードや顧客情報を含まないものを使います。

説明会では、VS Codeで `sample-todo-app/` だけを開いておきます。

```text
最初に少しだけ確認させてください。

Claude Codeを触ったことがある人も、今日初めて見る人もいると思います。

今日は経験差があって大丈夫です。

どのくらい触ったことがあるかだけ、軽く確認させてください。
```

聞くこと:

話す内容:

```text
ありがとうございます。

今日のゴールは、詳しい人に合わせることではありません。

まず全員が「安全に起動して、コードを変更せずにプロジェクトを説明してもらう」ところまで揃えることです。
```

補足:

- 挙手、Teams/Zoomのリアクション、チャットなど、場に合う方法で軽く確認する。
- 「分からない人いますか」と聞くより、「経験差があって大丈夫」と先に伝える。
- 回答を深掘りしすぎない。

## 0:03-0:06 今日のゴールとClaude Codeの位置づけ

話す内容:

```text
今日は、Claude Codeをチームで安全に試すための第1回です。

Claude Codeは、開発作業を手伝ってくれるAIエージェントです。

チャットで質問するだけではなく、プロジェクトのファイルを読んだり、必要に応じて編集やコマンド実行まで支援できる点が特徴です。

ただし、第1回のゴールは、Claude Codeにいきなり実装させることではありません。

まずは自分の担当プロジェクトをClaude Codeに説明してもらうところから始めます。

コードを変更せずに、安全に触ってみるのが最初の一歩です。
```

補足:

- 今日はClaude Codeの全機能を説明する会ではない。
- AIエージェントという言葉は「作業を進めるために、ファイルやコマンドも扱えるAI」くらいの理解でよい。
- Skills、MCP、Hooksなどの細かい話は扱わない。
- まずは「正しい場所で起動して、変更なしで調査する」ところまで。

## 0:06-0:09 なぜ運用テンプレートが必要か

話す内容:

```text
Claude Codeは、ファイルを読んだり、編集したり、コマンドを実行したりできる強力なツールです。

便利な一方で、使い方を決めずに始めると、危険なコマンド、不要な変更、秘密情報の入力などが起きる可能性があります。

そのため、今回はルール、権限設定、作業手順、チェックリストをまとめた運用テンプレートを用意しています。
```

ここで見せる資料:

- `member-start-note.md`
- 必要なら `STRUCTURE.md` の全体構成だけ

深掘りしないこと:

- harnessの細かい概念説明
- 全ファイルの説明
- 権限設定の詳細

## 0:09-0:12 最初に避けたいこと

話す内容:

```text
最初は、取り消しにくい操作や影響範囲が大きい作業はClaude Codeに任せません。
```

見せるリスト:

- ファイル削除

- ファイルの大量移動、リネーム

- `git push --force-with-lease`

話す内容:

```text
AIがこうした操作を提案しても、その場で実行しません。
一度止めて、人間が確認します。
```

ここで伝えること:

- 怖がらせるのが目的ではない。
- 安全に試せる範囲を先に決めておくため。
- 最初は「書かせる」より「説明してもらう」。

## 0:12-0:15 実演の準備: 開く場所を確認する

画面で見せること:

1. VS Codeで `sample-todo-app/` だけを開く
2. Explorerで `.git/`、`CLAUDE.md`、`.claude/settings.json` があることを見せる
3. 統合ターミナルを開く
4. 現在の場所を確認する

PowerShellの場合:

```text
Get-Location
```

話す内容:

```text
Claude Codeは、対象リポジトリの一番上のフォルダで起動します。

VS Codeでいうと、フォルダーを開くときに選ぶ場所です。

C:\ や C:\ProjectsDEV のような広い場所では起動しません。
```

補足:

- VS Codeのmulti-root workspaceは初回では使わない。
- 1つのVS Codeウィンドウに1つのプロジェクトだけを開く。

## 0:15-0:18 実演1: plan modeで起動する

画面で実行:

```text
claude --permission-mode plan
```

話す内容:

```text
初回はplan modeで起動します。

これは、まず調査や方針整理をしてもらうための使い方です。

いきなりファイル編集を任せないところがポイントです。
```

もし起動できない場合:

- その場で深追いしない。
- インストール、ログイン、権限の問題として後で個別確認にする。
- 説明会では準備済み画面やスクリーンショットで進めてもよい。

## 0:18-0:21 実演2: ルールと権限を確認する

画面で実行:

```text
/memory
```

話す内容:

```text
まず、Claude Codeがこのプロジェクトのルールを読めているか確認します。

ここでCLAUDE.mdが見えていれば、プロジェクト用のルールが読み込まれています。
```

次に実行:

```text
/permissions
```

話す内容:

```text
次に、どの操作が許可されていて、どの操作が禁止されているかを確認します。

削除、force push、.envの読み取りなどが制限されていることを確認します。
```

ここで伝えること:

- `/memory` はルール確認
- `/permissions` は権限確認
- どちらも初回に確認する

## 0:21-0:25 実演3: 変更なしでプロジェクトを説明してもらう

Claude Codeに依頼:

```text
まずこのリポジトリの構成を調査してください。
変更はまだ行わず、主要なフォルダ、実行方法、テスト方法、注意点を整理してください。
```

話す内容:

```text
ここではコード変更を依頼していません。

Claude Codeにプロジェクトを説明してもらっています。

最初はこの使い方だけでも十分価値があります。
```

出力を見ながら話す観点:

- 主要フォルダを説明できているか
- 実行方法やテスト方法を拾えているか
- 変更なしで進んでいるか
- 不明点を勝手に決めつけていないか

もし出力が微妙な場合の追加依頼:

```text
変更はせず、READMEとpackage.jsonをもとに、初めて参加する開発者向けに説明し直してください。
```
