# AI開発利用ポリシー インフラ・DevOps向け

## 対象

この補足ポリシーは、CI/CD、クラウド、コンテナ、IaC、監視、デプロイ周りを扱うエンジニア向けです。

## AIに任せてよい例

- GitHub Actionsの修正案
- Dockerfileの改善案
- TerraformやCloudFormationのレビュー
- CIエラーの調査
- ログの読み解き
- 手順書の下書き
- 監視アラートの説明整理
- デプロイ手順のレビュー

## 注意すること

- 本番環境への変更はAIに実行させない。
- シークレットをAIに入力しない。
- IAM、権限、ネットワーク設定を人間が確認する。
- Terraform applyなどの変更適用は人間が実行する。
- 削除系のIaC変更は特にレビューする。
- CI/CDの認証情報をログに出さない。
- 監視ログや本番ログを貼る場合は個人情報、トークン、顧客情報を除去する。

## 禁止または事前確認が必要な操作

- `terraform apply`
- `terraform destroy`
- `kubectl delete`
- `helm uninstall`
- 本番環境へのdeploy
- クラウドリソース削除
- IAMポリシー変更
- DNS設定変更
- 証明書や秘密鍵の更新

## レビュー観点

- 本番環境に影響しないか。
- 権限が広すぎないか。
- シークレットが露出していないか。
- ロールバック手順があるか。
- 監視やアラートに影響がないか。
- コストが大きく増えないか。
- 既存のCI/CDフローを壊していないか。
