# AI開発利用ポリシー バックエンド向け

## 対象

この補足ポリシーは、API、バッチ、DBアクセス、認証認可、サーバーサイド処理を扱うエンジニア向けです。

## AIに任せてよい例

- APIハンドラのたたき台
- DTOや型定義の整理
- バリデーション追加
- 単体テストの下書き
- SQLの相談
- エラー処理の見直し
- ログ出力の改善案
- 既存処理の説明
- リファクタリング案の作成

## 注意すること

- 認証、認可を必ず人間が確認する。
- 入力検証を省略しない。
- SQLインジェクション対策を確認する。
- 個人情報や機密情報をログに出さない。
- トランザクション境界を確認する。
- マイグレーションは人間がレビューする。
- 本番データに影響する操作をAIに実行させない。
- API互換性を壊していないか確認する。
- 外部サービス連携のリトライ、タイムアウト、冪等性を確認する。

## レビュー観点

- 認証済みユーザーだけがアクセスできるか。
- 権限のないユーザーがデータを読めないか。
- 入力値チェックが十分か。
- エラー時に機密情報を返していないか。
- DB負荷が増えすぎていないか。
- 既存APIのレスポンス形式を壊していないか。
- テストで正常系、異常系、境界値を確認しているか。

## 確認コマンド例

```text
npm run test
npm run build
```

プロジェクトによっては、Docker環境でも確認します。

```text
docker compose up
docker compose run app test
```
