# AI開発利用ポリシー QA・テスト向け

## 対象

この補足ポリシーは、QA、テスト設計、テスト自動化、リリース前確認を担当するメンバー向けです。

## AIに任せてよい例

- テスト観点の洗い出し
- 正常系、異常系、境界値の整理
- 回帰テスト候補の作成
- テストデータ案の作成
- バグ再現手順の整理
- リリース前チェックリストの作成
- E2Eテストのたたき台
- 不具合報告文の整理

## 注意すること

- AIが作ったテスト観点に抜けがある前提で確認する。
- 実仕様、受け入れ条件、過去障害を必ず照合する。
- 個人情報や本番データをAIに入れない。
- 自動テストの結果だけで品質判断しない。
- 実機確認が必要なものをAIの説明だけで済ませない。
- 再現手順や期待結果を人間が検証する。

## レビュー観点

- 正常系だけでなく異常系もあるか。
- 境界値が含まれているか。
- 権限別、状態別、端末別、ブラウザ別の観点があるか。
- 過去障害の再発防止観点が含まれているか。
- データ破壊や誤送信につながる操作を確認しているか。
- テストデータに個人情報や機密情報が含まれていないか。

## 推奨プロンプト

```text
以下の仕様について、テスト観点を洗い出してください。
正常系、異常系、境界値、権限、回帰影響に分けてください。
```

```text
この不具合報告を、再現手順、期待結果、実際の結果、補足情報に整理してください。
```
