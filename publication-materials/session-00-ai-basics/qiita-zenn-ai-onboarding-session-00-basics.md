# AI初心者向けに「第0回: AIツールを使い始める前の基本」資料を作った話

## はじめに

Claude Codeをチームで安全に試す説明会を準備しているうちに、ひとつ手前の資料が必要だと気づきました。

Claude Codeの起動方法や権限確認を説明する前に、AIに慣れていない人には、そもそも次のような疑問があります。

- AIチャットとAIエージェントは何が違うのか
- GitHub Copilot、Cursor、Codex、Claude Codeはどう違うのか
- AIに何を聞けばいいのか
- AIの答えはどこまで信じていいのか
- 業務で使ってよい範囲はどこまでなのか

## 1. 第0回は「初心者のつまずき」への回答にした

第0回資料は、単なるツール紹介にはしませんでした。

聞き手が最初につまずきやすいポイントに対して、順番に回答していく構成にしました。

```text
使い始めるときのつまずき
↓
AIの種類と使い方例
↓
何から始めるのがよいのか
↓
使用時のコツや注意
↓
これから小さく試していく
↓
次回セッションの紹介
```

特に意識したのは、次の対応関係です。

```text
「ツールの使い方がわからない」
  → AIの種類と使い方例

「何を聞けばいいか分からない」
  → まずは気軽に聞いてみる
  → AIエージェントには作業として頼める
  → 業務改善で使える例

「どこまで信じていいか分からない」
「業務で使うのは少し不安」
  → うまく使うためのコツ
  → 最初に避けたいこと
  → AIの返答は鵜呑みにしない
```

この形にすると、資料が「AIツールの説明」ではなく、「初めて使う人の不安に答える資料」になります。

## 2. AIツールの種類をざっくり分けた

第0回では、AIツールを細かく分類しすぎず、まずは次の4つに分けました。

- AIチャット
- AIエディタ/IDE
- AIエージェント
- 複数AIを扱う作業環境

資料内では、理解を助けるために具体的な製品名も入れています。

たとえば:

- ChatGPT
- Claude
- Gemini
- GitHub Copilot
- Cursor
- Kiro
- Claude Code
- Codex CLI
- Codex app
- Gemini CLI
- Copilot CLI
- Kiro CLI
- Google Antigravity

ただし、製品名はあくまで例です。

AIツールは変化が速いので、資料のタイトルにも `2026/05版` と入れました。

## 3. AIエージェントは「作業として頼める」ことを説明した

AIチャットは、質問に答えてくれるものとして比較的イメージしやすいと思います。

一方で、AIエージェントは少し説明が難しいです。

Claude CodeやCodex CLIのようにターミナルから相談するものもあれば、Codex appやKiroのように作業画面から依頼するものもあります。

そこで資料では、起動コマンドそのものよりも、AIエージェントにどう頼めるのかを重視しました。

```text
このバグの原因を調べてください。
この機能を追加する方針を出してください。
この修正をお願いします。
```

複数AIを扱う作業環境については、内部構造を細かく見せすぎると分かりにくくなります。

そこで、最終的には次のような図にしました。

```text
人間
やりたいことを伝える

→ プロジェクトA 調査
  プロジェクトB 修正
  プロジェクトC レビュー

→ AIが作業

→ 人間が確認
```

ここで伝えたいのは、AIが勝手に全部やるというより、作業ごとにプロジェクトを分け、人間が最後に確認するという見方です。

## 4. 注意点は「禁止」ではなく「安全に試すため」にした

AI活用の説明資料は、注意点を強く書きすぎると、聞き手が身構えてしまいます。

一方で、何も注意しないのは危険です。

そこで、トーンは「使うな」ではなく「安全に試すために、最初はここを避けましょう」に寄せました。

最初に避けたいこととして、資料では次のようなものを挙げています。

- `git reset` / `git clean` / `git rebase`
- force push
- ファイルやディレクトリの削除
- 大きなリファクタリング
- `.env`、APIキー、トークン、秘密鍵
- 本番環境や本番DBへの操作

また、AIの返答を鵜呑みにしないことも強調しました。

特に大事だと思ったのは、AIは同意寄りに返ってくることがある、という点です。

そのため、資料には次のような聞き方を入れました。

```text
「問題点、リスク、反対意見も挙げて」と明示して聞く。
```

単に「この方針でよいですか」と聞くのではなく、「この方針の弱点も教えてください」と聞く。

これはAIを業務で使ううえで、かなり基本的な姿勢だと思っています。

## 5. 案内役を架空人物にして親しみやすさを出した

第0回資料には、架空の案内役も入れました。

これは少し遊びの要素ですが、AI初心者向けの資料では、説明者が人として見えることも大事だと思っています。

資料内では、架空の人物と架空会社であることを明記したうえで、次のようなプロフィールにしました。

```text
名前: 佐伯 悠人（架空の人物）
所属: 株式会社ネクストワークス AI活用支援チーム（架空の会社）
```

さらに、最近ハマっていることとして、次のような一文も入れています。

```text
AIにあえて厳しめの質問をして、どこで間違えるか観察すること
```

こういう少し人間味のある要素があると、資料全体が「上から教える」感じになりにくいと思いました。
